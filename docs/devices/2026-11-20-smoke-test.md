## 内存

使用 `dumpsys meminfo` 的主进程 PSS，单位 MiB，按 1024 KiB 换算。PSS 会随缓存、共享页面和垃圾回收波动；这不是 APK 大小，也不是整机内存占用。

- 首轮安装后首页：手机约 64MiB，旧盒子约 45MiB。
- 手机最终一轮往返，第 1 / 5 / 10 次约为 185 / 168 / 170MiB；发送 `RUNNING_CRITICAL` 内存回收通知后约 150MiB，随后空闲约 144MiB，仍能正常返回首页。
- 旧盒子追加 30 次往返，第 10 / 20 / 30 次约为 59.5 / 58.3 / 59.4MiB，未观察到持续递增。此前短时采样最高约 83MiB，回收后约 55MiB。
- 手机 WebView 使用独立渲染进程；测试页面的一次渲染进程采样约 90MiB，需在主进程之外另计。旧盒子的 WebView 在应用进程内。

这些结果覆盖简单页面和短时重复操作，不代表大型网页、视频播放或长时间运行的内存上限。

## 实测发现与修复

- TY1608 的系统安装器只声明了 `file://` APK 安装入口。Android 7 以下改用应用外部缓存中的 APK 文件，Android 7 及以上继续使用 FileProvider；已在盒子上看到系统更新确认页。
- 下拉弹窗补充透明背景以处理旧系统的外部点击，并继承全屏状态，防止手机系统导航栏遮挡工具按钮。两台设备均已通过再次点击关闭的截图验证。

## MIUI 原桌面修复与复测

手机在 One 为系统默认桌面时，打开 MIUI 原桌面会立即退出。系统日志明确显示 `Launcher.FullbackHome` 检测到默认桌面为 One，并判定 `needKillSelf = true`。

修复采用 MIUI 兼容接管：仅停用 One 的 HOME 别名，保留应用入口和桌面守护，让 MIUI 保持系统默认桌面身份。迁移前检查 MIUI「后台弹出界面」授权，避免原桌面能打开但 HOME 返回 One 被系统拦截；一键设置支持自动授权或引导至 MIUI 权限页。

已安装修复后的 Release 包：系统 HOME 解析为 MIUI，守护诊断显示接管开启、后台弹出界面已授权。从 One 打开原桌面并停留 3 秒，再按 HOME 返回 One，连续 3 次均通过；没有使用会暂停无障碍服务的 UIAutomator 参与这组守护测试。

## DBX5 Pro 开机目标、方向键与报错复测

- 当前开机目标为 One 浏览器（`module:browser`）。修复两条漏触发路径：首页先到达、开机信号后到达时，单独检查目标是否已处理；开机前台记录滞留在系统 `FallbackHome` 时，按开机占位页处理。目标倒计时与首页到达分别记录，同一开机周期仅展示一次，HOME 返回不会重复启动。
- 第一轮实际重启复现 `FallbackHome` 滞留；修复后第二轮实际重启，约 uptime 50 秒触发倒计时并进入 BrowserActivity。
- 用户反馈开机报错后，抓到 One 的真实崩溃：尚未解锁时，守护服务经 `InstallHandoff.active` 提前读取 CE SharedPreferences。增加解锁保护并调整守护检查顺序。第三轮实际重启无该 One Java 崩溃；约 uptime 19 秒触发目标倒计时，随后进入 BrowserActivity。按 HOME 返回 One 后，左右键已送达，处理耗时均低于 1ms，未再次跳入目标。
- 曾发生系统认为 One 窗口有焦点、客户端却丢弃 `no window focus` 按键的状态；切换窗口后恢复。本轮记录窗口焦点变化，以便区别焦点丢失与 UI 长任务。
- 首次应用目录改为异步后，默认焦点可能提前落到设置按钮。修复为第一批图标就绪后聚焦首个图标；之后刷新保留用户当前图标焦点。
